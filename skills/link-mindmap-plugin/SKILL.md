# link-mindmap 插件操作指南

## 核心概念

link-mindmap 是 Obsidian 思维导图插件，通过 **frontmatter 字段** 存储笔记间的父子关系，将扁平的笔记文件组织成树形/网络结构并可视化。

### 关系存储机制（双向存储）

笔记间的关系通过 frontmatter 双向存储，**不依赖文件夹结构**：

| 方向 | 字段 | 格式 | 示例 |
|------|------|------|------|
| 父→子 | `children` | wikilink 数组 | `children: ["[[子笔记A]]", "[[子笔记B]]"]` |
| 子→父 | `parent` | 纯文本文件名 | `parent: "父笔记"` |

**关键规则**：
- `children` 用 `[[wikilink]]` 格式（关系图谱可见双向箭头）
- `parent` 用**纯文本**（非 wikilink，关系图谱不显示反向箭头）
- 一个笔记可以有多个 `children`，但 `parent` 只能有一个（首次设置的为原始父）
- 拖拽建立额外关联时，若目标已有 parent 则保留原始父不动

### 笔记文件结构

所有笔记**扁平存放**在 `mainFolder`（默认 `01-笔记`）下，不按父子建子文件夹。

文件 frontmatter 模板：
```yaml
---
children: []
parent: "父笔记名"
main: false
status: ""
date: 2026-10-28
type: ""
title: ""
---
```

**字段说明**：
| 字段 | 默认名 | 用途 |
|------|--------|------|
| 子链接 | `children` | 父笔记存放子节点 wikilink 数组 |
| 父链接 | `parent` | 子笔记存放父节点名（纯文本） |
| 主笔记标记 | `main` | `true` = 导图主入口节点 |
| 状态 | `status` | 笔记状态（可自定义状态颜色映射） |
| 日期 | `date` | 创建日期 YYYY-MM-DD |
| 类型 | `type` | 笔记类型（可自定义类型颜色映射） |
| 标题 | `title` | Excalidraw 笔记的显示标题 |

所有字段名均可在设置中自定义。

### Excalidraw 格式

Excalidraw 笔记扩展名为 `.excalidraw.md`，frontmatter 额外包含：
```yaml
excalidraw-plugin: parsed
tags: [excalidraw]
```
body 为 compressed-json 格式。链接名带 `.excalidraw` 后缀。

## 创建笔记

### 1. 创建独立笔记（根节点）

- **工具栏**：点击「新增」按钮（✚图标）
- **弹窗**：输入标题、类型、状态、模板、格式（md/excalidraw）、是否主笔记
- **结果**：在 `mainFolder` 下创建 `.md` 文件，`parent` 字段为空

### 2. 创建子节点

- **右键节点** → 「新增子节点」
- **快捷键**：选中节点后按 `Tab`
- **弹窗**：同独立笔记，但自动写入 `parent` 字段指向当前节点
- **同时**：父笔记的 `children` 数组自动追加新子节点的 wikilink

### 3. 批量创建笔记（缩进列表）

- **工具栏**：点击「批量建」按钮（📋图标）
- **命令面板**：搜索「批量创建笔记」
- **命令 ID**：`batch-create-notes`

**输入格式**：多层缩进列表，每行一个笔记，缩进表示父子关系。
支持 Tab 缩进或空格缩进（自动检测缩进单位）。

```
- 项目A
	- 需求分析
		- 用户调研
		- 竞品分析
	- 设计方案
		- 原型设计
		- UI设计
- 项目B
- 项目C
```

**解析规则**：
- 每行匹配 `^\s*[-*+]\s+(.+)$`
- Tab 展开为 4 空格，取最小非零缩进为 1 级
- 第 0 级 = 根笔记（无 parent），第 1 级 = 第 0 级的子节点，以此类推
- 同名笔记自动跳过创建，但仍建立父子关系

**弹窗选项**：类型、状态、模板、格式（md/excalidraw）、主笔记标记（仅对根笔记生效）

**创建顺序**：从根到叶递归创建。每个节点：
1. 生成 frontmatter（含 parent 字段）
2. 若有父节点，调用 `addLink` 给父笔记 children 数组追加 wikilink
3. `vault.create` 创建文件

## 查找与搜索

### 导图内搜索

| 操作 | 方式 |
|------|------|
| 搜索任意笔记作为导图根 | 工具栏「搜索」按钮（🔍） |
| 选择主笔记（main: true） | 工具栏「主笔记」按钮（📌） |
| 多选笔记同时显示 | 工具栏「多选」按钮（📋） |
| 按关键词索引过滤 | 工具栏「关键词」按钮（🔑） |
| 按类型/状态过滤 | 工作台（📊）中筛选 |

### 工作台

工具栏「工作台」按钮打开，包含：
- **统计面板**：笔记总数、类型分布、状态分布
- **时间线**：按日期排列所有笔记
- **筛选**：按类型、状态、日期范围、关键词过滤

### 节点定位

- 设置中开启 `autoLocate`：自动定位到当前打开的笔记
- 导图中点击节点：选中并显示右键菜单
- 双击节点：在 Obsidian 中打开该笔记

## 修改关系

### 拖拽连线

在导图中拖拽节点 A 到节点 B：
- A 成为 B 的子节点
- B 的 `children` 追加 A 的 wikilink
- 若 A 无 parent，写入 A 的 `parent` 字段
- **若 A 已有 parent**：保留原始父不动，仅追加 children 关联（额外关联）

### 批量移动

1. 工具栏「批量」按钮进入批量模式
2. 单击选中多个节点
3. 点击「移动到…」选择目标父笔记
4. 批量修改选中节点的 parent 和目标父笔记的 children

### 批量删除

1. 批量模式下选中多个节点
2. 点击「删除选中」
3. 笔记移入回收站，同时清理父笔记的 children 引用

### 批量改类型/状态

批量模式下可统一修改选中节点的 type 或 status 字段。

### 重命名

右键节点 → 「重命名」：
- 更新文件名
- 自动更新所有引用该笔记的 wikilink
- 更新 parent 字段引用

## 导图模式

工具栏模式下拉可选 5 种布局：

| 模式 | 说明 | 适用场景 |
|------|------|----------|
| **树形图** | 经典树形布局，父子垂直/水平排列 | 层级清晰的结构化笔记 |
| **分叉图** | Y型分叉，每个分支独立泳道 | 思路分叉、多分支并行 |
| **分支图** | Git 分支风格，时间轴+泳道+合并 | 版本演进、卢曼卡片盒 |
| **链路图** | 统一分支图风格，链路视图 | 单链路深入追踪 |
| **网络图** | 力导向布局，物理模拟，圆点+标签 | 复杂网络关系、交叉引用多 |

### 网络图特殊操作

- **拖拽节点**：拖拽时其他节点受力重新排列（力导向迭代）
- **触控支持**：手机端可触摸拖拽
- **连线长度**：由「水平间隔」设置控制

### 重复节点虚线

当笔记被多个父节点引用时，导图中显示为重复节点（alias），用虚线连接到主节点。

## 技术细节（给 Agent 的实现说明）

### 关系读写 API

**读取关系**（`collectNotes` 函数）：
- 遍历 `mainFolder` 下所有 `.md` 文件
- 从 `metadataCache.getFileCache(f).frontmatter` 提取 `children` 和 `parent`
- `extractLinks` 同时支持 `[[wikilink]]` 数组和纯文本

**写入子链接**（`addLink` 函数）：
```js
await app.fileManager.processFrontMatter(file, (fm) => {
  const arr = toArr(fm[field]);
  if (!arr.includes("[[" + target + "]]")) arr.push("[[" + target + "]]"));
  fm[field] = arr;
});
```

**写入父链接**：在 `_buildNewNoteBody` 中直接拼 frontmatter 文本：
```js
if (parentBasename && settings.autoAddBackLink)
  lines.push(backField + ': "' + parentBasename + '"');
```

### 文件命名

`safeFileName(name)` 替换非法字符 `\ / : * ? " < > | # ^ [ ]` 为 `-`。

### 批量创建解析

`parseBatchList(text)` 解析缩进列表为树结构：
1. 匹配每行 `^(\s*)[-*+]\s+(.+)$`
2. Tab 展开为 4 空格
3. 取最小非零缩进为 1 级单位
4. 用栈构建父子树

### 构建流程

1. 修改 `src.js`（源文件，被 .gitignore 忽略）
2. 运行 `cd build && node esbuild.config.js` 构建输出 `main.js`
3. `main.js` 是提交到 git 的编译产物
4. `i18n.js` 是国际化文件（被 .gitignore 忽略）
5. `styles.css` 修改不需要构建，直接生效

### 版本规则

- 版本号纯数字，无 `v` 前缀（如 `1.1.3`）
- 修改后先构建 `main.js`，等用户测试确认再升版本号
- 升版本：修改 `manifest.json` 的 `version` 字段 + git tag

## 常见操作示例

### 示例1：批量创建项目结构

输入：
```
- 项目A
	- 需求分析
	- 设计方案
	- 开发实现
		- 前端
		- 后端
	- 测试上线
- 项目B
	- 调研
	- 立项
```

结果：创建 8 个笔记，项目A 和项目B 是根笔记，需求分析/设计方案/开发实现/测试上线是项目A 的子节点，前端/后端是开发实现的子节点。

### 示例2：理解现有笔记关系

要理解笔记间的关系：
1. 读取笔记的 frontmatter，查看 `children` 和 `parent` 字段
2. `children: ["[[子A]]", "[[子B]]"]` = 该笔记有两个子节点
3. `parent: "父笔记"` = 该笔记的父节点是「父笔记」
4. 在导图中可视化查看树形结构

### 示例3：修改笔记关系

将笔记 B 从父节点 A 移到父节点 C：
1. 在导图中拖拽 B 到 C
2. 或批量模式下选中 B，点击「移动到…」选择 C
3. 插件自动更新：A 的 children 移除 B，C 的 children 追加 B，B 的 parent 改为 C

### 示例4：查找某笔记的所有子节点

1. 在 Obsidian 中打开该笔记
2. 查看 frontmatter 的 `children` 字段
3. 或在导图中以该笔记为根节点展开
4. 或用 Obsidian 搜索：`[children: 笔记名]`
